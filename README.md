# Блог на PHP

Сайт блога на чистом PHP, MySQL и Smarty. Без фреймворков. Единственная сторонняя библиотека — `smarty/smarty`.

## Запуск

Нужны Docker и Docker Compose.

Smarty ставится через Composer. Пакет `smarty/smarty` уже записан в `composer.json`, отдельно подключать его не нужно. Каталог `vendor` в репозиторий не входит, его создаёт `composer install`.

```bash
cp .env.example .env
composer install
docker compose up -d --build
docker compose exec php-fpm php bin/console database:migrate
docker compose exec php-fpm php bin/console database:seed
```

Сайт: [http://localhost:8000](http://localhost:8000).

phpMyAdmin: [http://localhost:8080](http://localhost:8080). Логин и пароль из `.env`: пользователь `app`, пароль `app`.

Повторный `database:seed` не выполняется, если в таблице `categories` уже есть строки.

Стили пишутся в `resources/scss/style.scss`. Контейнер `sass` сам собирает их в `public/css/style.css`.

Состав окружения:

| Сервис | Образ | Назначение |
| --- | --- | --- |
| `nginx` | nginx:alpine | Отдаёт сайт на порту 8000 |
| `php-fpm` | php:8.4-fpm | PHP и консольные команды |
| `mysql` | mysql:8.4 | База `app` |
| `sass` | node:22-alpine | Сборка SCSS |
| `phpmyadmin` | phpmyadmin:5 | Просмотр базы на порту 8080 |

Параметры подключения к базе читаются из `.env`: `DB_HOST`, `DB_PORT`, `DB_NAME`, `DB_USER`, `DB_PASSWORD`, `DB_ROOT_PASSWORD`. `APP_DEBUG=true` включает перекомпиляцию шаблонов Smarty.

## Страницы

| Адрес | Что показывает |
| --- | --- |
| `/` и `/home` | Категории, в которых есть статьи. У каждой категории — 3 последние статьи по дате публикации и кнопка «Все статьи». Сначала не больше 10 категорий, кнопка «Еще» подгружает следующие 10. |
| `/categories/{id}` | Название и описание категории, список статей, сортировка и пагинация. На странице 6 статей. |
| `/articles/{id}` | Полная информация о статье и до 3 похожих статей. |

Сортировка на странице категории: `?sort=date` или `?sort=views`. Номер страницы: `?page=2`. По умолчанию сортировка по дате публикации.

Похожие статьи — другие статьи из тех же категорий. Выше стоят те, у которых общих категорий больше.

Обычное открытие статьи в браузере счётчик увеличивает. Браузер при этом делает два запроса, и число в базе меняет только второй.

`GET /articles/{id}` только собирает страницу и показывает уже сохранённое число. Сам этот запрос счётчик не увеличивает.

После загрузки страницы `public/js/article.js` отправляет `POST /articles/{id}/views`. Этот запрос прибавляет 1 и подставляет новое число на страницу. Повторная отправка того же токена число не меняет.

## Архитектура

Запрос проходит так:

1. `public/index.php` создаёт запрос и отдаёт его ядру.
2. `App\Http\Kernel` находит маршрут в `routes/web.php` и вызывает контроллер.
3. Контроллер берёт данные у сервиса и возвращает HTML или текст.
4. Сервис работает с интерфейсами репозиториев.
5. Реализация репозитория выполняет SQL через PDO.
6. HTML собирает Smarty из `resources/views`.

Слои:

| Каталог | Роль |
| --- | --- |
| `src/Http` | Маршруты, контроллеры, запрос и ответ, обработка 404, 405 и прочих ошибок, сессия просмотра |
| `src/Domain` | Сущности, сервисы, интерфейсы репозиториев. SQL здесь нет |
| `src/Infrastructure` | PDO, Smarty, контейнер, чтение `.env`, миграции |
| `src/Console` | Команды `database:migrate` и `database:seed` |
| `resources/views` | Шаблоны Smarty |
| `resources/scss` | Исходники стилей |
| `public` | Точка входа, CSS, JS, изображения |
| `database/migrations` | Создание таблиц |
| `database/seeds` | Пример категорий и статей |
| `config/container.php` | Связка интерфейсов с реализациями |

Контроллеры тонкие: они не содержат SQL. Запросы к базе остаются в классах `Pdo*Repository`.

Счётчик просмотров:

- в куке `session_id` хранится только id сессии, срок жизни 24 часа;
- при открытии статьи создаётся одноразовый токен и кладётся в `<meta name="csrf-token">`;
- скрипт `public/js/article.js` отправляет его в заголовке `X-CSRF-TOKEN`;
- пара «сессия и токен» ищется в `session_token_links`;
- повтор того же токена счётчик не увеличивает;
- обновление страницы и новое окно получают новый токен и увеличивают счётчик;
- nginx ограничивает частоту запросов к странице статьи и к `POST` счётчика.

Подгрузка категорий на главной — `public/js/home.js`.

## Постановка задачи

Нужен простой рабочий сайт на чистом PHP без фреймворков, с MySQL и Smarty. Это блог с категориями и статьями.

Стек по условию:

- PHP 8.1+
- Smarty
- MySQL
- без фреймворков

В проекте PHP 8.4.

Данные:

- категория: название, описание;
- статья: изображение, название, описание, текст, одна или несколько категорий, количество просмотров.

Обязательные страницы:

- главная: категории, в которых есть статьи, и 3 последних поста по дате публикации; кнопка «Все статьи» у каждой категории;
- категория: название, описание, список статей, сортировка по просмотрам и по дате публикации, пагинация;
- статья: вся информация и блок из 3 похожих статей.

Дополнительно: заполнение базы примерами категорий и статей.

Оцениваются простота и читаемость кода, структура проекта, работа с MySQL, самостоятельность решения и глубина понимания. Плюсом идут SCSS и Docker.

Дополнительных пояснений к условию нет.

## Что добавлено к условию

1. Таблица `files` добавлена умышленно, в урезанном виде. Ссылки на изображения обычно хранятся отдельно. Путь можно было записать прямо в `articles`, но файлы вынесены в свою таблицу.
2. Связь статей и категорий многие-ко-многим вынесена в отдельную таблицу. В условии про неё не сказано, но у статьи может быть несколько категорий, и у категории несколько статей.
3. В статьи добавлено поле `published_at`. Сортировка по дате в условии есть, а самого поля в описании данных нет.
4. У таблиц есть `id`, чтобы собрать связь многие-ко-многим. В условии про идентификаторы не сказано.
5. Из условия неясно, какие поля статьи показывать на главной. Показываются имеющиеся данные карточки.
6. В базе хранятся полные дата и время публикации. На страницах выводится только дата. В условии это не оговорено.
7. Для счётчика просмотров добавлены кука, сессия и таблицы сессий и токенов. Увеличение идёт через `POST`.
8. Похожие статьи выбираются из тех же категорий. Выше те, у которых общих категорий больше.

## Как делалось решение

Использовался Cursor, модель Grok.

1. За основу взят пустой шаблон PHP-проекта. Это коммит `Empty template for a PHP project`.
2. Функциональность добавлялась по очереди, с пониманием, что и куда добавлять.
3. JavaScript используется для счётчика просмотров и для кнопки «Еще» на главной, чтобы сразу не загружать все категории. В условии назван только Smarty.
4. Накрутка ботами ограничена частично. Лимит стоит на загрузку статьи в nginx и на `POST` счётчика: токены создаются при открытии страницы, а частота накрутки режется на `POST`.
5. Код в основном написан по командам к ИИ. Ручной набор классов вместе с отладкой занял бы около недели и всё равно опирался бы на документацию и прошлый опыт. Опыта разработки без ИИ достаточно, чтобы оценивать, что сделано правильно.
6. Лишняя логика возможна: задание расплывчатое, а критерии оценки частично противоречат друг другу. Простота и структура проекта ничего не говорят о безопасности и о том, насколько проект должен расширяться.

## Замечания по индексам

Если таблица `articles` станет большой и сортировка или выборка замедлятся, это нужно проверить через `EXPLAIN`. Под списки тогда полезны ещё два индекса:

- `(published_at, views, id)` — страница категории с сортировкой по дате: `published_at DESC, views DESC, id DESC`;
- `(views, published_at, id)` — та же страница с сортировкой по просмотрам: `views DESC, published_at DESC, id DESC`.

Три последние статьи на главной идут в порядке `published_at DESC, id DESC`. Этот порядок закрывает отдельный индекс `(published_at, id)`.
